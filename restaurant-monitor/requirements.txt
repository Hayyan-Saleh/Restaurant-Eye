# Generated via `pip freeze` from a clean `.venv` built against every import

# Notes on non-obvious entries:
#   - setuptools is pinned <81 (80.10.2) because deep-sort-realtime's
#     PyTorch embedder does a bare `import pkg_resources` at runtime;
#     setuptools>=81 dropped pkg_resources and that import fails.
#   - gdown and tensorboard are not imported directly by our code, but
#     torchreid's package __init__ unconditionally imports them
#     (torchreid/reid/data/datasets/image/university1652.py -> gdown;
#     torchreid/reid/engine/engine.py -> torch.utils.tensorboard ->
#     tensorboard). torchreid does not declare either as a dependency,
#     so `import torchreid` (used by src/kbs/reid_gallery.py) fails
#     without them installed explicitly.
#   - redis is imported directly by src/core/central_identity_store.py
#     (Task 8's cross-process shared identity store) and by
#     src/run_all_cameras.py, but was never declared here. Pinned to the
#     version already resolved in the dev environment via `pip show redis`,
#     same approach as every other entry in this file.
#   - scikit-learn is not imported by name anywhere in src/, but
#     models/label_encoder.pkl was pickled from a sklearn LabelEncoder;
#     `pickle.load()` on it in LivePipeline.__init__
#     (src/core/live_pipeline.py) needs sklearn importable to unpickle,
#     even though no source file writes `import sklearn`. Found via a live
#     end-to-end run of the real pipeline while verifying Task 5's
#     orchestrator (see docs/TASK5_REPORT.md) -- static import-grepping
#     alone doesn't catch dependencies implied only by pickled objects.
